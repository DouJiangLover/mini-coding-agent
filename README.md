# IntentFlow

IntentFlow 是一个从零实现、采用交互优先工作流的本地编程智能体。用户提交任务后，系统会在需要时先澄清需求并生成终端用户流程，经确认后再进入实现；模型只能通过本项目定义的工具观察和修改工作区，宿主程序负责对话历史、Skill 选择、工具解析、本地执行、安全边界、失败恢复、终止条件和事件记录。React 工作台通过 SSE 实时展示整个过程。

GitHub：https://github.com/DouJiangLover/mini-coding-agent

完整的工作原理、核心设计和模块框架见 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)。
复杂故障实验的场景、真实运行轨迹和改进分析见 [`docs/FAILURE_LAB.md`](docs/FAILURE_LAB.md)。

本项目没有使用 LangChain、LlamaIndex、OpenAI Agents SDK、AutoGen 等 Agent 框架，也没有使用服务端托管的文件或代码执行工具。

## 已实现能力

- DeepSeek V4 / OpenAI-compatible 原生 Tool Calling，同时保留坏 JSON 参数错误反馈
- `list_files`、`read_file`、`search_text`、`create_file`、`apply_patch`、`run_command`、`finish` 七个本地工具
- Bug Fix、Test Writer、Documentation、Frontend Build 四个可插拔且可组合的 Skill
- 独立 Skill 管理页：动态启用/停用内置能力，通过表单创建或从本地文件导入可持久化的自定义 Skill
- 多 Skill 混合路由：支持任务前手动锁定一项，自动模式结合关键词与模型语义组合 1–3 项互补能力
- Skill 渐进式加载：常驻上下文只放名称与适用描述，模型需要某项能力时再通过 `load_skill` 读取完整策略
- FlowPet 多任务伙伴：不同工作区任务可并行运行，集中展示进度，并提醒等待确认、完成与失败状态
- 树形 Session：对话与运行历史持久化，既能“继续完成”，也能从任意历史节点创建分支且不覆盖原路线
- 运行中 Steering：Agent 工作时可继续发送方向修正，消息会在下一次模型决策前生效并写入 Session 审计记录
- 结构化上下文压缩：超出预算后保留目标、计划进度、已读/已改文件、成功命令和最近错误，完整历史仍留在 Session
- 独立 Agent 设置页：四种运行模式、三项质量关卡和四项执行预算均可本地调整
- Interaction-First 工作流：筛选出从零构建的前端产品任务，先展示终端用户流程图和验收标准，用户确认后才写代码
- 需求追踪闭环：为确认后的验收标准生成 AC 编号，把文件实现、测试/构建和人工复读证据关联起来；证据不完整时拒绝结束任务
- 可信 Hook 管线：独立的 `before_tool_call` 和 `after_tool_call` 接口承载参数/重复动作/质量前置检查，以及状态归档与需求证据收集；每次工具事件记录实际经过的 Hook
- 显式任务状态机、计划进度、可调步数预算和连续失败停止条件
- 观察、失败基线、根因定位、修改、验证、完成前自检六段质量闭环
- 质量关卡阻止盲目修改、未验证完成和未经复读的结果提交
- Skill 外操作与受限命令的单次授权：暂停、展示完整参数，按钮或 Enter/Esc 快捷键决策后继续原任务
- 工作区路径隔离、凭据文件保护、命令分级校验、超时和输出截断
- SSE 实时事件流、工具时间线、命令输出和文件 Diff
- JSONL 运行审计日志，保存在 `.intentflow/runs/`
- 无 API Key 也能运行的离线演示模式

## 快速运行

需要 Python 3.11+、Node.js 22+。

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
npm install
python dev.py
```

打开 [http://localhost:3000](http://localhost:3000)。后端 API 位于 `http://127.0.0.1:8000`。

点击“新建任务”后会先打开本地工作区选择器。可以从预置项目中选择，也可以浏览或输入 `INTENTFLOW_WORKSPACE_ROOT` 下的相对文件夹路径；点击“新建项目工作区”可输入文件夹名称，系统会在 `workspaces/` 中创建一个不含 Agent 源码的空项目目录，立即选中并返回任务输入框。在根目录列表中可以删除一个完整项目，系统会二次确认并把它移到 `.intentflow/workspace-trash/`，而不是立即永久删除；正在执行任务的工作区不能删除。左侧会长期显示所有顶层项目工作区，FlowPet 会统计所有后台任务。当前任务运行时仍可选择另一个工作区继续提交，原任务不会被停止。FlowPet 任务中心显示每个任务的执行步骤、最近事件和状态，点击即可切换回来。为了避免文件冲突，同一工作区同一时间只允许一个运行中的任务。

每个工作区会恢复其最近一次对话。任务完成、失败或停止后，可以在同一输入框继续补充要求；例如输入“继续完成”，后端会创建一轮关联运行，继承原始目标、上一轮总结、计划、错误、改动文件以及已确认的交互模型。Agent 仍会重新读取当前文件，且不会继承一次性命令授权。事件和对话关系保存在 `.intentflow/runs/*.jsonl`，因此切换工作区、刷新页面或重启后端后仍可恢复；如果后端在执行中重启，该轮会记为“已中断”，用户可从原工作区继续。

任务正在运行且没有等待专门确认时，输入框会切换为 Steering 模式。此时发送的内容不会创建新任务，而是在下一次模型决策前加入当前 Run 的上下文，例如“不要修改后端，优先完善移动端交互”。Steering 不会中断已经开始的工具调用，也不能替代权限确认或绕过安全、验证和 README 交付关卡；收到与生效都会成为 SSE/JSONL 事件并保存在当前 Session 节点中。

点击工作台侧边栏的“Skill 管理”，或直接打开 [http://localhost:3000/skills](http://localhost:3000/skills)，可以调整 Agent 的可用能力。既可以填写表单创建，也可以选择本地 `.zip`、`.json`、`.md` 或 `SKILL.md` 文件导入。修改会保存在本地 `.intentflow/skill-config.json`，不进入 Git；启用状态与新建 Skill 从下一个任务开始生效。

任务输入框底部可以选择“自动组合 Skill”或手动指定一项已启用能力。手动选择具有最高优先级；自动模式先通过触发词生成候选，再由真实模型结合任务语义、Skill 描述和候选得分选择 1–3 项互补能力。例如“修复错误并补充测试”可以同时装配 Bug Fix 与 Test Writer。系统合并这些 Skill 的策略和默认工具集合，但工作区隔离、危险命令拦截与单次授权仍由宿主统一控制。候选、最终组合、置信度和选择理由都会记录在执行轨迹中。

终端用户流程图不属于 Frontend Build 或任何其它 Skill。Interaction-First 是 Skill 路由之前的独立宿主阶段，只根据任务语义、工作区是否已有实现以及是否存在需求文档决定是否触发。描述简略但工作区含需求文档、且用户要求继续实现时，也会先从文档生成流程供确认；修复、补测试、解释、局部样式调整和已有项目修改则直接跳过。这样流程图是否出现不会受 Skill 误选影响。

点击“Agent 设置”，或直接打开 [http://localhost:3000/settings](http://localhost:3000/settings)，可以选择标准、安全、自主或只读模式，并调整 Interaction-First、强制验证、完成前自检、最大步骤、失败上限、上下文预算和命令超时。配置保存在 `.intentflow/agent-settings.json`，每个新任务启动时读取一次快照，运行中的任务不会被中途改变。默认步数预算为 45；复杂 Web 项目建议调到 60。保存过的页面配置优先于 `INTENTFLOW_MAX_STEPS`，环境变量只在尚未保存设置时提供首次默认值；任务启动事件会展示本轮实际生效的步数。

首次运行不需要 API Key：`INTENTFLOW_DEMO=auto` 会在没有密钥时启用离线演示。选择 `calculator` 工作区，输入修复失败测试的任务，即可看到 Agent 实际执行测试、读取代码、修改文件并重新验证。

实际项目都位于本地 `workspaces/`，该目录只包含相互隔离的项目，不包含 Agent 源码，并且不会提交到 Git。仓库中的 `examples/` 仅作为初始化模板；首次创建 `workspaces/` 根目录时会复制内置项目，但不会覆盖已有工作，也不会在重启后重新创建用户已删除的项目。`star-catcher` 是网页游戏修复用例；`2048-game` 初始只有需求文档；`approval-demo` 用于演示单次授权；`order-engine-lab` 用于复杂故障实验。

Interaction-First 的筛选原因会记录在执行轨迹中。确认页只展示终端用户流程图和验收标准，内部状态规则仍用于实现约束但不再作为图形展示。复杂流程采用自动分层分支布局，返回与跨阶段路径使用外围通道；节点说明支持多行，点击页面可聚焦直接流转，也可以缩放画布并在编号列表中查看完整操作。选择“符合预期，继续实现”后，系统才组合 Skill 并进入代码阶段；选择“需要调整”并填写意见，会生成完整的新版本再次确认。

## 使用真实模型

复制环境变量模板，但不要提交真实凭据：

```bash
cp .env.example .env
```

默认已按 DeepSeek 配置。在本地 `.env` 或终端环境中设置：

```text
INTENTFLOW_DEMO=false
DEEPSEEK_API_KEY=你的密钥
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-v4-flash
```

当前后端直接调用 DeepSeek 的 OpenAI-compatible `chat/completions` 接口，并在工具循环中使用非思考模式。连接失败、请求超时、限流和服务端错误会进行最多三次短退避重试；仍然失败时，前端会显示可操作的故障说明，而不是空白异常。也可通过 `LLM_API_KEY`、`LLM_BASE_URL` 和 `LLM_MODEL` 接入其他兼容服务。API Key 只用于请求头，不进入日志、模型上下文或前端事件。

## 核心流程

```text
接收任务
  → 宿主判断是否需要 Interaction-First，并按需等待用户确认/修改流程
  → 手动指定 Skill，或由 SkillRouter 候选评分 + 模型语义路由选择
  → 常驻上下文只注入 Skill 元数据，需要时调用 load_skill 获取完整策略
  → AgentLoop 构造系统约束、任务与工具 schema
  → 先理解项目；修复类任务运行测试建立修改前基线
  → 模型返回原生 tool_calls
  → before Hook 管线检查参数、重复动作与修改前质量条件
  → ToolRegistry 校验；需要额外权限时暂停并等待用户单次授权
  → 授权通过后执行原始动作，拒绝则把结果反馈给模型重新规划
  → after Hook 管线归档状态并更新“验收项 → 实现文件 → 验证结果”证据账本
  → finish 前检查所有必选验收项；缺实现或缺新鲜验证时返回执行循环
  → 修改后强制验证，并在首次 finish 时进入完成前自检
  → 结构化结果写回对话上下文
  → EventStore 记录并通过 SSE 推送前端
  → 继续执行，直到 finish、取消、超步数或连续失败
```

前端只展示事件，不参与 Agent 决策。模型也不能直接读写文件或运行命令；所有副作用都经过 ToolRegistry 和 WorkspaceGuard。

## Skill 格式

每个 Skill 是 `skills/<name>/` 下的一组元数据和专用提示词：

```text
skill.json  名称、关键词、允许工具、可视化计划
prompt.md   该领域的执行策略
```

路由采用“手动优先、自动混合”的策略。自动模式使用关键词评分缩小候选范围，真实模型只读取任务和候选元数据进行语义选择，不会在路由阶段接触文件工具。选择结果会记录关键词、路由方式、理由和置信度。选中后，名称、描述、执行计划和最小工具权限进入本轮运行；完整提示词不常驻上下文，模型必须通过只允许读取已选项的 `load_skill` 工具按需加载。

管理页允许填写名称、适用场景、触发词、执行策略和默认工具权限，也支持导入不超过 1 MB 的 ZIP、JSON 和 Markdown Skill。ZIP 只读取同一能力包中的 `skill.json`、`prompt.md` 或 `SKILL.md`，其它文件不会解压或执行；越界路径、符号链接、加密包和异常膨胀的压缩包会被拒绝。外部工具名称会映射为本项目支持的最小工具集合。自定义 Skill 不会绕过宿主安全策略；未默认开放的工具仍需单次授权，工作区越界和凭据访问仍然直接拒绝。系统也会阻止用户停用最后一个可用 Skill。

## 安全设计

- API 只接受 `INTENTFLOW_WORKSPACE_ROOT` 下的相对工作区
- 不同工作区允许并行执行；相同或父子目录重叠的工作区互斥，避免两个 Agent 同时修改相同文件
- 工作区删除只接受顶层项目目录，运行中项目会被拒绝，内容先移入可恢复的本地回收区
- 每次文件访问都会在解析软链接后再次检查边界
- 拒绝 `.env`、`.git`、密钥证书等敏感路径
- `create_file` 只创建受支持的 UTF-8 文本文件，拒绝覆盖已有文件并限制单文件大小
- 命令使用参数数组执行，不经过 shell，因此管道和命令拼接不会生效
- 常见开发命令默认执行；Skill 外工具、内联脚本、Git 写操作等需要用户逐次授权
- 安全模式会为写文件和运行命令逐次确认；只读模式从宿主层禁止写文件；自主模式仍不能绕过硬安全边界
- 工作区越界、凭据文件和高风险删除参数属于硬边界，授权也不能绕过
- 单条命令超时可在 5–60 秒间调整，文本输出最多保留 12,000 字符
- 同一个工具调用连续出现三次会被阻止
- 连续失败上限可在 1–10 次间调整；达到失败或最大步骤预算时安全停止
- 测试未通过属于正常诊断反馈，不计入连续工具失败

该安全层是轻量级保护，不等同于容器或操作系统级沙箱。请只把可信项目目录放入工作区。

## 可答辩的设计取舍

1. **SSE 而不是 WebSocket**：当前通信是单向事件推送，SSE 实现更少、自动重连、足够可靠。
2. **创建与修改分离**：`create_file` 只负责不存在的新文件，已有文件必须通过唯一文本补丁修改，从协议层避免静默覆盖。
3. **显式状态机而不是无限循环**：状态、步数、重复动作和失败计数共同提供可解释的停止边界。
4. **Skill 只提供策略与权限**：Agent 内核不依赖具体任务类型，新 Skill 不需要修改循环代码；手动或语义路由只决定装配哪一项能力。
5. **事件流与决策解耦**：可视化故障不会影响 Agent，JSONL 还能用于回放和复盘。
6. **交互先于代码**：Frontend Build 将“需求 → 代码”拆成“需求 → 用户交互模型 → 人工确认 → 实现 → 对照验证”，降低需求理解偏差。
7. **可调策略不等于可调安全边界**：设置页控制工作节奏和自主程度，路径隔离、凭据保护与危险命令拦截始终由宿主强制执行。
8. **完成必须有证据**：模型可以建议工具与 AC 的关联，但宿主根据真实工具结果维护账本；普通环境探测不算验证，修改会使旧验证失效，必选项未闭环时 `finish` 只会得到质量检查反馈。
9. **Hook 与 Skill 隔离**：Hook 是宿主注册的可信 Python 中间件；用户 Skill 只能提供提示词、元数据和声明式权限，不能注入可执行 Hook 代码或绕过安全层。
