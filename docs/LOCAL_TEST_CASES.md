# IntentFlow 本地综合测试用例

## 用例一：已有系统新增功能并修复旧问题

工作区：`expense-flow`

首次输入：

> 请按照 CHANGE_REQUEST.md 为现有记账系统增加月度分类预算，同时修复编辑交易后分类统计不更新的问题，补充必要测试并确保原有功能不退化。不要重写整个项目。

预期观察：

1. 已有实现会让 Interaction-First 自动跳过。
2. 自动路由应选择 Bug Fix，并可能组合 Test Writer 或 Frontend Build。
3. Agent 先运行 `npm test`；基线至少包含“编辑分类失败”和“预算 API 缺失”两类问题。
4. Agent 阅读变更需求、源码和测试，进行局部修改，而不是整项目覆盖。
5. 修改后再次运行测试，更新页面预算交互和 README，并完成复读自检。
6. 可在运行中发送 Steering：`预算面板保持紧凑，不要改动现有交易数据格式。`

验收：`npm test` 全绿；页面可设置并展示预算；分类编辑 Bug 修复；原有测试继续通过。

## 用例二：模糊需求经过用户澄清后从零构建

工作区：`study-board-brief`

首次输入：

> 我想做一个小组任务网页，方便大家知道课程作业还有哪些事情没做。具体应该有哪些页面和功能我还没想清楚，你先帮我整理一下大家会怎么使用，确认后再开始制作。

Agent 返回第一版流程图后，点击“需要调整”，只补充产品功能：

> 我们一般是 4—6 个人一起完成课程作业，不需要注册账号。一打开网页，我希望能分别看到还没开始、正在做和已经完成的任务。每项任务要能写名称、负责人、截止时间、重要程度和备注，也要能修改、删除和更换进度。我还想按负责人查看任务，并在误删后马上撤销。页面上最好能看到整体完成情况和最近快到期的任务。

检查第二版流程是否覆盖看板、任务编辑、筛选、删除撤销和本地数据；符合后点击“符合预期，继续实现”。

确认流程并进入执行阶段后，等待 Agent 完成项目检查、开始创建文件。此时不要停止任务，直接在底部输入框发送 Steering：

> 我刚想到，我们平时更多是在手机上查看任务。页面不要太挤，按钮和文字大一些，新增任务也尽量简单。你按这个方向继续做吧。

预期观察：

1. 确认流程前工作区仍然只有需求文档。
2. 用户反馈会产生完整第二版流程，而不是只追加一句说明。
3. 确认后自动组合 Frontend Build、Test Writer、Documentation 等相关 Skill。
4. Agent 创建页面、样式、逻辑、测试和 `README.md`，并运行真实验证命令。
5. 需求证据面板把验收项关联到实现文件和验证结果。
6. Steering 发送后先显示“收到方向修正”，下一次模型决策前显示“方向修正已进入上下文”；任务不会中断或重新开始。
7. README 交付关卡检查功能介绍、环境准备、启动方法、使用步骤和常见问题后才能完成。

验收：交互与确认版本一致；自动测试通过；刷新后数据保留；移动端可用；README 可供非开发人员照着启动和使用。
