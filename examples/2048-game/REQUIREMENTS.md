# 2048 小游戏需求文档

## 1. 项目目标

从零实现一个可直接在现代浏览器中运行的 2048 小游戏。本工作区初始只包含本需求文档，开发者需要自行规划并创建完整项目文件。成品应无需后端服务、无需联网资源，具备清晰的代码结构和自动化测试。

## 2. 技术约束

- 使用原生 HTML、CSS 和 JavaScript ES Modules，不使用 React、Vue、Canvas 或外部 CDN。
- 不安装第三方运行时或测试依赖；测试使用 Node.js 内置的 `node:test` 与 `node:assert/strict`。
- 游戏核心逻辑必须与 DOM 渲染分离，能够在 Node.js 中直接导入测试。
- 提供 `package.json`，执行 `npm test` 必须运行全部测试。
- 页面入口为 `index.html`，直接通过本地静态服务器即可试玩。

## 3. 游戏规则

- 棋盘固定为 4×4，共 16 个格子。
- 新游戏开始时随机生成两个数字块；数字 2 的概率为 90%，数字 4 的概率为 10%。
- 支持上、下、左、右四个方向移动。所有数字块先向目标方向压缩，相同数字在一次移动中只能合并一次。
- 每次合并产生的新数字累加到当前分数。例如两个 8 合并为 16，本次增加 16 分。
- 只有棋盘实际发生变化时，才在空格中新增一个随机数字块；无效移动不能生成新块。
- 出现 2048 数字块时进入胜利状态，显示提示，但允许玩家选择继续游戏。
- 棋盘没有空格且任意相邻格都无法合并时进入失败状态。
- “新游戏”按钮应清空当前棋盘和分数并重新生成两个初始数字块。

## 4. 操作方式

- 桌面端支持方向键以及 W/A/S/D，按键时不要滚动页面。
- 移动端支持在棋盘区域向四个方向滑动，短距离误触不应触发移动。
- 游戏结束后仍可使用“新游戏”重新开始。

## 5. 页面与视觉

- 页面包含游戏标题、当前分数、历史最高分、新游戏按钮、4×4 棋盘和状态提示。
- 视觉风格简洁温暖，不同数值的数字块应有明显的颜色层级；高数值仍需保证文字可读。
- 数字块出现和合并时提供克制的动效，并尊重 `prefers-reduced-motion`。
- 桌面端居中显示，移动端在 320px 宽度下不能横向溢出，棋盘保持正方形。
- 按钮具有清晰的 hover、focus-visible 和 disabled 状态；状态提示使用可访问的语义。

## 6. 数据与状态

- 历史最高分保存到 `localStorage`，刷新页面后仍然存在。
- 如果存储不可用或内容无效，游戏应回退到 0，不能因此崩溃。
- 纯逻辑模块不得直接访问 DOM 或 `localStorage`。

## 7. 自动化测试验收

至少覆盖以下行为：

1. 新棋盘尺寸正确，并且初始化后恰好包含两个数字块。
2. 单行向左移动时，`[2, 2, 2, 2]` 变为 `[4, 4, 0, 0]`，增加 8 分。
3. `[2, 2, 4, 0]` 变为 `[4, 4, 0, 0]`，同一个数字块不会在一次移动中重复合并。
4. 四个方向的移动结果正确，可通过固定棋盘验证。
5. 有效移动会新增一个数字块，无效移动不会新增数字块。
6. 生成随机数字块时可以注入可预测的随机函数，便于稳定测试 2/4 概率分支。
7. 能正确识别 2048 胜利状态与无可用移动的失败状态。
8. `npm test` 最终全部通过。

## 8. 完成标准

- 所有需求均有实际实现，不接受静态示意页面或伪代码。
- 文件结构清楚，核心函数命名可读，没有把全部逻辑堆在单个事件处理器中。
- 页面可玩，键盘和触摸操作完整，响应式布局正常。
- 自动化测试全部通过，测试不能为了迁就错误实现而降低正确预期。
